# Подпись для Smart App Control

«Интеллектуальное управление приложениями» (Smart App Control, SAC) может запрещать неизвестный неподписанный код. Это отдельная проверка Windows: результат антивирусного сканирования `found no threats` её не заменяет. Для неизвестного приложения требуется подпись доверенного издателя. Самоподписанный сертификат на компьютере разработчика эту задачу распространения не решает.

## Состояние 0.6.2

Локальный `VoxPad-0.6.2-Setup-x64.exe`, лаунчер и плагины NSIS не подписаны. Комплектный Python имеет подпись Python Software Foundation, но она не распространяется на лаунчер или остальные компоненты. Проверка установщика Defender 18 ноября 2026 года сообщила `found no threats`; это не проверка разрешения SAC на другом компьютере.

Локальная проверка Authenticode полного каталога 0.6.2: 419 EXE/DLL/PYD, из них 271 с действующей подписью и 148 без подписи. Неподписанные компоненты включают лаунчер, расширения NumPy/SciPy, sherpa-onnx и аудиобиблиотеки. Отчёт сохранён в `work/signature-audit-0.6.2.json`; это локальный результат, без воспроизведения на компьютере пользователя и без утверждения, какой именно файл там заблокирован.

Уже скачанный Setup не изменится после правок исходников. Для подтверждённой блокировки неизвестного неподписанного компонента поддерживаемый путь — новый релиз с доверенной подписью и проверка установки/запуска на Windows 11 с включённым SAC. Точный заблокированный файл сначала устанавливается по журналу целевого компьютера. Пока это не проверено, исправление распространения не завершено. [Диагностика](windows-install-diagnostics.md).

## Настройка издателя

Открытая лицензия исходников не является цифровой подписью Windows. SignPath Foundation требует открытую лицензию и одобрение проекта, но также запрещает подписывать сторонние библиотеки сертификатом проекта. Поэтому простое подключение бесплатной программы не решает автоматически подпись всех 148 сторонних и собственных компонентов. Для SignPath нужно отдельно согласовать состав артефактов и подписи upstream-зависимостей. [Условия фонда](https://signpath.org/terms).

Нужен Code Signing сертификат доверенного удостоверяющего центра с доступным приватным ключом. Выпуск сертификата требует регистрации и проверки личности/организации владельца. Приватный ключ и пароль нельзя помещать в репозиторий или отправлять в чат. Возможен также сервис Microsoft Artifact Signing; текущий скрипт реализует подпись сертификатом из хранилища Windows, интеграция сервиса потребует его настройки.

На доверенном Windows-компьютере сборки установите SignTool из Windows SDK и предоставьте сертификат в `Cert:\CurrentUser\My` (в том числе через провайдер аппаратного ключа). Укажите публичный отпечаток сертификата:

```powershell
$env:VOXPAD_SIGN_CERT_SHA1 = '<40 шестнадцатеричных символов отпечатка>'
# Если SignTool не находится автоматически:
$env:VOXPAD_SIGNTOOL = 'C:\Program Files (x86)\Windows Kits\10\bin\<версия>\x64\signtool.exe'
pwsh.exe -NoProfile -NonInteractive -File scripts/windows/sign.ps1 -Mode Check
```

`SHA1` в имени переменной — формат отпечатка для выбора сертификата. Содержимое файлов и RFC 3161 timestamp подписываются SHA-256. По умолчанию используется `http://timestamp.digicert.com`; другой RFC 3161 адрес можно задать через `VOXPAD_SIGN_TIMESTAMP_URL`.

## Порядок сборки

1. Используйте новую версию в `outputs/source/app.py`; опубликованные файлы прежнего релиза не заменяйте.
2. Выполните `scripts/build_runtime_portable.py`. После проверки RECORD сборщик подписывает неподписанные EXE, DLL и PYD, сохраняя действующие подписи поставщиков. Затем создаёт манифест, ZIP и SHA-256. Повреждённые или недействительные подписи приводят к остановке, а не заменяются.
3. Выполните `scripts/build_online_setup.py <полный ZIP>`. Проверяются реальные подписи внутри ZIP. Подписываются worker, частные копии плагинов NSIS, встроенный деинсталлятор и итоговый Setup. Контрольная сумма Setup вычисляется после подписи.
4. Выполните функциональные проверки, Defender и установку/диктовку/удаление на Windows 11 с включённым SAC. При отказе проверьте журнал `Microsoft-Windows-CodeIntegrity/Operational`: событие 3077 содержит конкретный заблокированный файл; 3076 относится к режиму оценки.
5. Перед публикацией `scripts/windows_signing.py --archive <ZIP> --setup <Setup.exe>` проверяет подписи реальных артефактов. `github_release.py` делает эту проверку до сетевых запросов. Проверка подписей не является гарантией отсутствия вредоносного кода или любого предупреждения SmartScreen.

Для локальной разработки оба сборщика принимают `--allow-unsigned`. Такие файлы могут блокироваться SAC и не проходят проверку публикации. Этот флаг не меняет настройки защиты Windows.

В GitHub Actions задайте repository variables `VOXPAD_SIGN_CERT_SHA1`, при необходимости `VOXPAD_SIGNTOOL`, `VOXPAD_SIGN_TIMESTAMP_URL`, а `VOXPAD_RELEASE_RUNNER` — метку доверенного Windows runner с доступом к ключу. Обычный `windows-latest` не содержит сертификата издателя; без настройки workflow намеренно останавливается до сборки. Используйте изолированный runner для релизов, которому не передаются задания из недоверенных pull request.
