# VoxPad: производительность ASR на Core Ultra 5 125H

Замеры 16–17 ноября 2026. Исходный коммит `0e8bf25`, локальная ветка `optimize/dictation-latency`.
Работа выполнялась с полной версией из GitHub. После уточнения приоритетов дальнейшая работа сосредоточена на ASR; оформление интерфейса не менялось.

## 1. Что обнаружено

- В исходном стенде примерно 96–98% пути обработки занимала нейросеть. Ускорение основной части дало сочетание размещения на P-ядрах и отключения активного ожидания потоков ONNX Runtime.
- Один лишь переход на P-ядра ухудшал скорость. Одно отключение spinning давало большой разброс. Проверены обе настройки отдельно и вместе двумя проходами в прямом и обратном порядке.
- В выигравшем режиме сравнивались 1/2/4/6/8 потоков с пересозданием runtime. У четырёх и шести потоков близкие медианы коротких запросов; выбран более простой вариант с четырьмя потоками. Автоматический `num_threads=0` валидатор CPU-модели sherpa не поддерживает.
- Нативный ORT-профиль русской записи 4,76 с: encoder **0,875 с**, decoder **0,044 с**, joiner **0,038 с**; полный inference **0,962 с**. Прогрев отделён секундной паузой и исключён из этих сумм. Профилирование добавляет собственные расходы; компоненты определяются по операторам графа. Encoder занимает около 90,9% inference.
- В профиле действительно выполняются `DynamicQuantizeMatMul`, `ConvInteger`, `DynamicQuantizeLSTM` на CPU. Использование конкретных машинных инструкций VNNI через этот API не измерялось.
- SQLite и завершение RecoveryWriter стояли перед вставкой. Изолированный стенд с заглушками ASR/Windows-вставки, реальными SQLite/fsync и 31 повтором: медиана **29,4 → 2,7 мс**. Это инфраструктурный тест, а не полная пользовательская задержка.

## 2. Что изменено

- `outputs/source/cpu_runtime.py`, `engine.py`, `app_features.py`: автоматический профиль **только для проверенного Core Ultra 5 125H, Parakeet, sherpa-onnx 2.0.1 и четырёх потоков**. Индексы P-ядер запрашиваются у Windows; код не содержит их фиксированного списка. Настройка затрагивает только процесс VoxPad. При переключении на Whisper/GigaAM и ошибке загрузки восстанавливается маска CPU. Другие компьютеры сохраняют исходную настройку в два потока. Нет изменений плана питания Windows. Конфигурация ORT создаётся временно при загрузке модели и удаляется после создания сессий.
- `engine.py`: раздельные таймеры подготовки, создания stream, передачи waveform, inference и нормализации; сохранены `resample_poly`, mono float32 и штатный секундный прогрев. Повторного прогрева перед каждой диктовкой нет. Необязательный повреждённый `performance.json` больше не блокирует загрузку модели.
- `app.py`, `app_features.py`, `windows_input.py`, `diagnostics.py`: время Windows-события, hook, доставки в Tk и этапов обработки измеряется монотонными часами. Остановка принимает последний callback до завершения PortAudio. Аудиоблок копируется один раз для ASR и восстановления. Диктовка получает снимок модели, окна назначения и окончания текста.
- `media_jobs.py`, `storage.py`, `app_features.py`: запуск ASR не ждёт финального fsync, а готовый текст не ждёт SQLite. Существующий поток диктовки завершает сохранение в фоне. Файлы восстановления удаляются после сохранения результата и завершения writer. При ошибке SQLite текст остаётся доступен, дополнительно сохраняется локальный файл `data/unsaved`; повтор после запуска идемпотентен. Ошибки записи и повторное распознавание сохранённого аудио покрыты тестами.
- `activity_window.py`, `settings_actions.py`, `ui_language.py`: только необходимые запреты работы с ещё сохраняемым журналом и сообщения ошибок; без изменений оформления.
- `text_processing.py`: устранена безусловная подстановка «ё» для `<unk>` в других языках, изолированном маркере и парных маркерах кавычек. Прежняя эвристика внутри русских слов сохранена; её нельзя считать универсальным восстановлением неизвестного символа.
- `scripts/benchmark_asr.py`, `prepare_public_benchmark.py`, `profile_onnx.py`, `benchmark_infrastructure.py`, `record_benchmark_samples.py`: воспроизводимые локальные замеры, профилирование и запись трёх собственных эталонов. Новых зависимостей нет; psutil уже входит в зависимости pycaw.
- Регрессионные тесты: `test_cpu_runtime.py`, `test_dictation_latency.py`, `test_benchmark_metrics.py` и обновления существующих тестов записи/постобработки.

## 3. Сравнение производительности

|---|---:|---:|---:|
| ASR записи 2,5 с, p50 | 1,18 с | 0,38 с | −67,7% |
| ASR записи 5 с, p50 | 2,16 с | 0,71 с | −67,2% |
| ASR записи 8 с, p50 | 3,10 с | 1,01 с | −67,3% |
| ASR записи 13 с, p50 | 5,72 с | 1,66 с | −71,0% |
| ASR русской записи 4,76 с, p50 | 2,14 с | 0,62 с | −70,8% |
| ASR английской записи 3,85 с, p50 | 1,81 с | 0,55 с | −69,6% |
| p95 ASR, равная смесь пяти записей 2,5–8 с | 3,31 с | 1,08 с | −67,4% |
| WER / CER, два эталона | 3,70% / 0,84% | 3,70% / 0,84% | Без изменения |

| CPU процесса, 100% = один логический CPU | 241% | 208% | −13,9% |
| Физическое отпускание → видимый текст в стороннем приложении | Не измерено | Не измерено | Не измерено |

По 7 повторов на каждой из 6 записей. Перед измерением использован только штатный секундный прогрев, без дополнительной речевой разминки. Медианный RTF короткого корпуса: **0,432 → 0,143**.

Предыдущая серия из 7 повторов с теми же успешными настройками inference дала для 2,5/5/8/13 с соответственно **0,55 / 0,93 / 1,59 / 2,31 с**. Повтор в таблице выполнен на окончательных версиях `engine.py` и `cpu_runtime.py`; хеши этих двух файлов проверены. Между сериями уточнён только путь отката CPU при ошибке подготовки, который не выполнялся при измерениях. Оба набора включены в JSON. Скорость зависит от фоновой нагрузки и состояния CPU; улучшение относится к медиане и p95 данного корпуса. Ещё выполнены повторные проходы конфигураций в обратном порядке. RSS опрашивается каждые 10 мс; CPU — среднее процесса, взвешенное по времени запросов. Энергопотребление не измерялось.

Хеши расшифровок совпали на всех шести записях до/после. WER/CER доступны только для двух открытых эталонов (27 слов): русский WER 10%, английский 0%. Четыре фрагмента 2,5/5/8/13 с вырезаны в отдельные файлы из реальной шумной английской речи и не имеют проверенного эталона. Исходные WAV сохранены. Это ограниченная проверка точности; смешанная речь пользователя пока не размечена.

После 30 секунд простоя два распознавания русской записи заняли **0,73 с, 0,72 с**. Оснований добавлять постоянный фоновый прогрев не получено; простой в несколько минут отдельно не измерен.

Подробные числовые результаты и параметры: [benchmarks/asr-2026-11-17.json](benchmarks/asr-2026-11-17.json). Полные локальные прогоны и ORT-трассы находятся в `work/benchmarks/`. Экспорт модели: полная согласованная ревизия `ed5d745623472f97cfc2e6c2916ee248798fc5a8`, SHA-256 файлов сохранены в отчёте. Штатный GitHub-архив при подготовке не прошёл проверку размера; контроль целостности загрузчика не ослаблялся. Для замеров получен полный закреплённый набор файлов из зеркала автора экспорта с проверкой хешей.

## 4. Проверки

- **72 автоматических теста прошли**: повторное использование микрофона, последний callback, короткая запись, параллельный fsync, медленная/неработающая SQLite, повтор сохранения после COMMIT, сохранность результата без аудиовосстановления, следующая диктовка и смена модели во время сохранения, защита загрузки модели во время повтора несохранённых результатов, окончание текста, ошибки буфера обмена, CPU-профиль и откат маски.
- Настоящий Parakeet выполнен локально; проверен и обычный путь CPU-профиля приложения после удаления временного ORT-конфига. Профилирование успешно работало из пути с кириллицей и пробелом.
- Whisper/GigaAM проверены на уровне сохранения исходных factory-параметров; настоящие веса этих моделей и полная переносимая сборка в этой работе не проверялись.
- До уточнения приоритетов UI smoke/recording smoke прошли. Один ранний UI regression дал `TclError: can't delete Tcl command`; исходный коммит и повторный прогон прошли. После уточнения дальнейшая работа над интерфейсом прекращена.
- Один сравнительный headless-прогон старого приложения завершился timeout; последующий короткий прогон прошёл. Эти данные не используются как подтверждение полной пользовательской задержки. Реальный микрофон, физическая клавиша и фактическое появление текста в стороннем приложении не измерены.

## 5. Что осталось проверить вручную

1. Один раз записать три собственных эталона: `python scripts/record_benchmark_samples.py --output-dir work/my-speech`. Скрипт запишет короткую русскую фразу, смешанную техническую и длинную; предложит уточнить эталонный текст. Затем все конфигурации сравниваются автоматически.
2. Проверить одну обычную диктовку в Блокнот: начало/конец фразы и нужное окончание. Для локального отчёта запустить приложение с `--diagnostics work/latency.jsonl`. Лог не содержит аудио и расшифровок. Windows input timestamp имеет миллисекундную точность; окончание SendInput означает отправку команды, не подтверждение отрисовки другим приложением.

## 6. Нереализованные идеи

- Отдельная привязка к P-ядрам и отдельное отключение spinning не выбраны: первая ухудшала задержку, второе давало нестабильные результаты. Комбинация проверена отдельно.
- 6/8 потоков не дали убедительного выигрыша коротких запросов относительно четырёх в итоговом режиме.
- Пятисекундные окна/перекрытия не включены: для 2–5 с окна не дают раннего завершённого фрагмента; для длинной речи нет размеченного корпуса, подтверждающего сохранение контекста и отсутствие ошибок на границах. Нативное streaming-состояние не имитируется.
- Модель и движок не заменялись. Альтернативный per-channel INT8 экспорт проверен по описанию; опубликованный тест на небольшой венгерской выборке не доказывает преимущество для русской/английской речи на этом CPU. Encoder отдельно не подменялся.
- Постоянный ASR-worker, дополнительная языковая модель, шумоподавление/VAD, NPU/OpenVINO не добавлены: подтверждённой пользы для выбранного сценария не получено.

## Повторение замера

```powershell
.venv\Scripts\python.exe scripts\prepare_public_benchmark.py
.venv\Scripts\python.exe scripts\benchmark_asr.py --manifest work\benchmarks\manifest.json --model-dir work\benchmarks\model --threads 4 --app-profile --repeats 7 --warmups 0 --output work\benchmarks\repeat.json
.venv\Scripts\python.exe scripts\profile_onnx.py --model-dir work\benchmarks\model --audio work\benchmarks\originals\russian.wav --threads 4 --app-profile --output-dir work\new-ort-profile
```

Подготовка открытых файлов требует интернета один раз; распознавание и повторные замеры работают локально. Бенчмарк не меняет настройки приложения. `performance.json` сохраняет явный приоритет `threads`; `cpu_profile: "standard"` отключает автоматический профиль.

Основания для настроек: [потоки ONNX Runtime](https://onnxruntime.ai/docs/performance/tune-performance/threading.html), [Windows CPU Sets / EfficiencyClass](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-system_cpu_set_information), [per-channel INT8 экспорт](https://huggingface.co/zmakra/sherpa-onnx-parakeet-tdt-0.6b-v3-int8pc).
