# Разработка

VoxPad использует Tkinter, Windows API через ctypes и sherpa-onnx. Аудио с микрофона получает sounddevice, файлы декодирует PyAV. Модели выполняются на CPU.

Основные файлы:

- `app.py` — запуск, цикл событий, базовая запись.
- `app_features.py` — настройки, переключение моделей и обработка результатов.
- `main_window.py`, `settings_window.py`, `activity_window.py` — окна приложения.
- `ui_style.py` — палитры, масштабирование и общие элементы интерфейса.
- `ui_language.py` — единый каталог русских и английских текстов.
- `audio_input.py` — подготовка остановленного микрофона и повторное использование потока.
- `recording_overlay.py` — капсула записи с масштабированием по разрешению текущего монитора и отрисовкой с повышенной детализацией.
- `storage.py` — настройки, история и статистика.
- `model_manager.py`, `engine.py` — загрузка моделей и распознавание.
- `media_jobs.py` — обработка файлов и сохранение незавершённых записей.

Все эти файлы находятся в `outputs/source/`. `app_paths.py` выбирает папку данных: `outputs/Transcriber/` для исходников и папку рядом с EXE для собранного приложения. Ресурсы интерфейса берутся из каталога модулей (`_internal/assets/` в EXE-сборке). Абсолютные пути к рабочей машине не нужны.

## Проверки

Запускайте команды из корня проекта с установленными зависимостями:

```powershell
.venv\Scripts\python.exe -m compileall -q outputs\source
.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
.venv\Scripts\python.exe tests\ui_smoke.py
.venv\Scripts\python.exe tests\ui_regression.py
.venv\Scripts\python.exe tests\recording_smoke.py
```

Модульные тесты проверяют хранение, статистику и установку ZIP обновлений. UI-проверка открывает настоящие Tk-окна с временными данными, подменяет движок распознавания и проверяет настройки, поиск истории, экспорт, окончания текста, паузу и смену языка. Ей нужен Windows-сеанс с рабочим столом. Микрофон, реальные горячие клавиши и точность моделей проверяются отдельно.

`test_review_regressions.py` проверяет отказы распознавания, истории, настроек и буфера обмена, блокировку параллельного восстановления, отключение старого AI-флага и локальное время в таблице истории. `test_audio_input.py` также проверяет нажатие и выход во время подготовки устройства. Эти тесты не используют настоящие записи, API или системный буфер обмена. GitHub Actions устанавливает зависимости до запуска тестов.

Метки истории хранятся в UTC и переводятся в часовой пояс компьютера при отображении. Старые записи не переписываются. В восстановлении показывается местное время начала сохранённой записи. Внешняя AI-обработка и её старый интерфейс удалены; сохранённые профили и записи в диспетчере учётных данных Windows не затрагиваются.

В конце `Engine.transcribe()` применяется `normalize_transcript()` из `text_processing.py`: «ё/Ё» сохраняются, а маркер `<unk>` заменяется на «ё» с учётом регистра слова и начала предложения. Это правило действует для всех моделей, диктовки, файлов и восстановления; существующая история не переписывается.

Главное окно создаёт `main_window.py`. В `CoreApp` оставлены жизненный цикл записи, микрофон и очередь событий; старого резервного интерфейса и второго пути распознавания нет. Служебный выбор микрофона пока использует скрытый Combobox. Обновление из ZIP находится в `updates.py`, сборка — в `scripts/package_update.py`.

`ui_regression.py` проверяет увеличение интерфейса на 50% относительно 0.5.1 (масштаб 97,03125% от исходного), ограничение начального размера рабочей областью монитора, нативный цикл изменения размеров всех окон, конечную геометрию и автоматическое следование теме Windows. Переключение темы тестируется подменой чтения реестра; настройки Windows не меняются. Несохранённый текст, параметры, сочетания клавиш и положение окон должны переживать смену оформления.

Капсула масштабируется независимо от интерфейса: эталон — 234 × 117 пикселей на экране пользователя 2880 × 1920. Коэффициент равен меньшему из отношений ширины и высоты текущего монитора к эталону; тень и отступ снизу масштабируются вместе с капсулой. Используется монитор окна назначения, а при записи кнопкой — активного окна. Размер и фон пересчитываются при каждом появлении. Отдельный DPI-контекст нативного окна исключает дополнительное растяжение Windows на мониторах с разным масштабом, не меняя DPI-контекст Tk.

Стекло и волна рисуются минимум в 468 × 234 пикселях и как минимум с удвоенной детализацией относительно экранного размера. Финальный кадр уменьшается через LANCZOS, поэтому маленький экран не снижает внутреннее разрешение отрисовки. `test_overlay_scaling.py` проверяет шесть разрешений, исходный размер на эталонном экране, второй монитор с отрицательными координатами, выбор активного монитора, повторный расчёт после смены экрана, прозрачность и восстановление DPI-контекста.

`recording_smoke.py` проверяет начало записи при нажатии кнопки и горячей клавиши, отпускание в режиме удержания, режим переключателя, повторное использование аудиопотока, восстановление и очистку после ошибки устройства. Звук синтетический; системный буфер обмена и пользовательские данные не меняются.

Микрофон открывается заранее в остановленном состоянии и запускается при нажатии. После отпускания поток останавливается и сохраняется для следующей записи; во время ожидания аудио не захватывается. Смена устройства, пауза и выход освобождают подготовленный поток. Используется низкая задержка драйвера с возвратом к стандартной, если такой режим не поддерживается. Капсула видна уже в первом кадре и за примерно 110 мс плавно поднимается на 6 пикселей и достигает полной непрозрачности. Для стекла копируется только её область экрана, а форма и рисунок волны сохранены.

В `resize_support.py` на время перетаскивания границ фиксируются контейнеры и откладывается перерисовка. После отпускания восстанавливается компоновка с окончательным размером. Обработчик не блокирует запись или фоновую обработку. Скруглённые поверхности используют кэш небольших углов вместо растрового изображения размером со всю панель.

## Обновления

Версия задаётся в `app_features.py`. После её изменения:

```powershell
.venv\Scripts\python.exe scripts\package_update.py
```

Пакет содержит Python-модули, значок и звуки с SHA-256 в `manifest.json`. Модели, настройки и история в архив не попадают. Он предназначен для исходников. Собранное приложение обновляется заменой файлов из нового переносимого архива с сохранением `data/` либо повторной установкой. Перед обновлением закройте VoxPad.

## Переносимая сборка с отдельным Python

Начиная с 0.5.3 основной локальный формат — `scripts/build_runtime_portable.py`. Сборщик копирует неизменённые исполняемые файлы Python, стандартную библиотеку, Tcl/Tk, проверенные по RECORD зависимости, открытые модули приложения и Parakeet. Импорт изолирован файлом `python312._pth`: установленные Python, пользовательские PYTHONPATH/PYTHONHOME и текущая папка не добавляют модули в runtime. Готовый архив — `outputs/VoxPad-<версия>-Windows-x64-runtime.zip`.

Запуск: `VoxPad.cmd`. Для диагностики — `VoxPad-debug.cmd`. Папки `runtime`, `app`, `models` и `launch.py` остаются рядом. `data` хранится в корне приложения, автозапуск вызывает поставляемый Python и `launch.py --tray`; системные ассоциации Python не нужны. Цифровые подписи скопированных Python EXE/DLL сохраняются, собственный подписанный EXE не создаётся.

Проверка: `tests/runtime_portable_smoke.py <ZIP> <публичный WAV> --report <JSON>`. Она сверяет весь BUILD-MANIFEST, извлекает программу в путь с кириллицей и пробелами, проверяет игнорирование постороннего Python-окружения, загрузку модели и настоящее распознавание. Дополнительно проверяются трей и клавиатурный обработчик при выключенной записи и без обращения к микрофону. Для CI без рабочего стола предусмотрен `--skip-session-check`.

Defender-проверка новой сборки должна выполняться отдельно, с включённой защитой. Успех функциональных тестов не заменяет проверку антивирусом. Смена упаковки не устанавливает причину обнаружения старого EXE и не является подтверждением его безопасности. Версия 0.5.2 остаётся отмеченной как проблемная; см. `defender-0.5.2.md`.

## Предыдущая сборка EXE и установщик Windows

Нужны Windows x64, Python 3.12 x64 и установленная модель Parakeet. Сначала скачайте модель через приложение из исходников — сборщик не загружает её сам. [NSIS 3](https://nsis.sourceforge.io/Download) нужен только для установщика.

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.venv\Scripts\python.exe scripts\build_windows.py --format portable
```

Если модель находится в другом каталоге, передайте `--model-dir "путь к папке модели"`. В папке должны лежать `encoder.int8.onnx`, `decoder.int8.onnx`, `joiner.int8.onnx`, `tokens.txt`.

PyInstaller собирает приложение в `work/windows-dist/VoxPad/`. По умолчанию создаются готовая папка `outputs/VoxPad-<версия>-portable/`, архив `outputs/VoxPad-<версия>-Windows-x64-portable.zip` и контрольная сумма `.zip.sha256`. В ZIP лежит папка `VoxPad/` с EXE, `_internal/`, `models/`, лицензиями и короткой инструкцией. Можно переносить всю папку и запускать её без установки; переносить один EXE из неё нельзя. Python и native DLL входят в сборку. Модель хранится отдельно от runtime и не распаковывается заново при каждом запуске. Личные настройки и история не включаются.

Для установщика используйте `--format installer --nsis "C:\Program Files (x86)\NSIS\makensis.exe"`, для обоих вариантов — `--format both` с тем же путём к NSIS. Установщик создаётся в `outputs/VoxPad-<версия>-Setup-x64.exe` вместе с `.exe.sha256`.

Для проверки переносимого архива: `tests/portable_smoke.py <ZIP> <тестовый WAV>`. Проверка извлекает ZIP в отдельную папку с пробелами и кириллицей и запускает EXE с очищенным окружением Python. Используйте публичную или синтезированную речь. При распространении через GitHub приложите ZIP к Releases; исходники из Code → Download ZIP не содержат бинарных зависимостей и модели.

Установка выполняется для текущего пользователя в `%LOCALAPPDATA%\Programs\VoxPad`. Она создаёт ярлыки и запись в списке установленных приложений. Удаление сохраняет пользовательские данные и дополнительно скачанные модели. Автозапуск EXE использует его собственный путь с `--tray`.

Для проверки запустите установленный `VoxPad.exe --smoke-test`: он создаёт `smoke-test.json` с результатом загрузки модели. С `--smoke-audio <путь к публичному речевому WAV>` также проверяются декодирование, распознавание и звуковой сигнал без записи истории. Не проверяйте сборку только через исходники.

`tests/installer_smoke.py <установщик> <тестовый WAV>` проверяет установку в отдельную папку, реальный EXE при очищенных переменных Python, повторную установку с сохранением данных и удаление. Для автоматической установки используется `/S /TESTMODE /D=<абсолютный путь>` (`/D` должен быть последним). `/TESTMODE` не создаёт ярлыки и запись в реестре. Перед проверкой закройте запущенный VoxPad. Не публикуйте установщик без проверки на отдельной Windows-машине; изолированное окружение на машине разработчика не заменяет эту проверку.

В сборке сохранены лицензии библиотек и модели; для Parakeet включены источник и CC BY 4.0. Сертификат подписи в проект не входит. Установщик можно подписать отдельно перед публикацией.
