# Диагностика установки на другом компьютере

Работа 0.5.3 на том же компьютере полезна для сравнения: она запускалась через CMD и комплектный подписанный Python. В 0.6.0–0.6.2 добавлены собственные неподписанные EXE. Однако точный файл, заблокированный на другом компьютере, по локальным проверкам определить нельзя. Лицензия исходного кода на решение Smart App Control не влияет.

## Если ошибку показывает окно установщика VoxPad

1. Сразу после ошибки нажмите Win+R.
2. Введите `%TEMP%\VoxPad-setup-error.log` и нажмите Enter.
3. Сохраните тип исключения и строку с причиной. В новых диагностических сборках перед исключением указаны версия и этап установки.
4. Перед отправкой замените имя пользователя и личные пути на `***`. Аудио, историю диктовок и настройки приложения присылать не нужно.

Старое общее сообщение об интернете и месте на диске не определяет причину. `WebException` с HTTP-кодом или сетевым статусом указывает на загрузку; несовпадение контрольной суммы — на другой или повреждённый архив; отказ в доступе или `IOException` нужно разбирать по тексту исключения. Путь AppData/Local/Temp в конце сообщения обычно указывает, где сохранён журнал.

Если файла нет, это тоже сообщите. Не считайте старый журнал от другой попытки результатом текущей установки. Компонент установки мог быть остановлен до запуска, а запись журнала могла завершиться ошибкой.

## Если окно показывает Windows / Smart App Control

1. Запомните время попытки и имя запускавшегося файла.
2. Нажмите Win+R, введите `eventvwr.msc`.
3. Откройте «Журналы приложений и служб → Microsoft → Windows → CodeIntegrity → Operational».
4. Найдите событие 3077 с временем попытки. Нужны имя заблокированного файла и текст события; личные пути можно скрыть. Событие 3076 означает проверку в режиме оценки, а не фактическую блокировку.

Журнал CodeIntegrity показывает отдельные заблокированные файлы, а не итоговую причину любого сбоя установки. [Документация Microsoft](https://learn.microsoft.com/en-us/windows/apps/develop/smart-app-control/test-your-app-with-smart-app-control).

## Подготовленные изменения после 0.6.2

Диагностический Setup показывает конкретную причину из worker, отдельно сообщает о невозможности запуска worker и не выдаёт старый журнал за журнал текущей попытки. Сам NSIS создаёт отдельный `VoxPad-setup-bootstrap-<идентификатор>.log` ещё до извлечения worker и записывает туда результат запуска. Путь к этому журналу показывается при отсутствии ответа worker. Ошибка записи в TEMP не скрывает исходную причину. Ошибка очистки временных файлов не заменяет основную ошибку установки.

Полный ZIP той же версии рядом с диагностическим Setup выбирается автоматически. Это позволяет установить файлы без повторной загрузки с GitHub. ZIP проверяется по тому же SHA-256, что и при сетевой установке. У опубликованного Setup 0.6.2 локальный ZIP передаётся явно через `/ARCHIVE="<полный путь к ZIP>"`.

Использование локального архива устраняет необходимость сетевой загрузки, но не отменяет проверок Windows. У диагностического Setup нет доверенной подписи издателя; он не является исправлением блокировки SAC и не опубликован как новый релиз. Не меняйте настройки защиты ради его запуска.
